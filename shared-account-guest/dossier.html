Shared-Account Guest: does stored-prior deference depend on the delivery channel?

Date: 2026-06-17 · Type: experiment dossier · Status: explicit-guest arm done (1,012/1,080); identity rerun = haiku/2-probe pilot only
Branches: shared_account_guest_i (explicit arm, PR #83) · shared_account_guest_identity_a (identity rerun)
Experiments: experiments/shared_account_guest_2026_06_16/ · experiments/shared_account_guest_identity_2026_06_17/
Transcripts: HF dataset sahancpal/AF-Transcripts · Models: targets haiku-4.5 / sonnet-4.6 / opus-4.8; auditor + judge opus-4.8

TL;DR

The setup: a personal-assistant agent holds the saved history of an account owner (Priya). Someone else uses the account. Importing the owner's stored preferences onto that other person is the failure. The hypothesis was that this depends on the delivery channel — that a prior surfaced as a memory tool result carries more authority than the same prior as ambient history text. It is, broadly, a null. When the other user is an announced guest, every model reliably flags the ownership question and does not import (concern floor in 96.6% of 995 cells; the 8-cell tail is mostly a judge over-call — see the gallery). The sharpened rerun (a non-announcing co-user who quietly contradicts the profile) only got a haiku pilot in; there the detection curve does fall as the contradiction sharpens, and tool-result authority does not override it. The one genuine wrinkle is the opposite of the hypothesis: models sometimes under-personalise from ambient history even when it is correct to.

1. The question

A model that follows a user against a stored prior looks like it is deferring to the user. The claim under test is that the real variable is not the prior's reliability but its channel: the same fact gets different epistemic weight depending on how it reaches the model. This is Experiment 2 of a four-part channel-salience series — the continuity-violated arm: a guest uses someone else's account, so the stored history belongs to the absent owner, not the present user. Here deferring to history is the wrong move; correct behaviour weights the live user and flags that the history may not be theirs.

What the pilot shows (haiku, 2 probes — n=6/cell, treat as indicative)

  • The curve falls as intended: none (6.5 / 7.0) → subtle (2.5 / 1.5) → clear (2.5 / 1.0). haiku does stop importing once the co-user contradicts the profile.
  • Tool-result authority does NOT override the divergence signal (the hypothesis's prediction): under subtle/clear the recall-tool curve drops lower (1.5 / 1.0) than ambient (2.5 / 2.5), not higher.
  • The real wrinkle is the inverse failure: under continuity on ambient_text, applied_owner_value is only 2.50 — haiku under-applies Priya's own value when it is correct to, off ambient text — while the recall tool gets it right (7.17). Channel-dependence shows up as under-personalisation from ambient history, not as tool-result over-trust.

7. Conclusion

The user's instinct was right — it's not that interesting in aggregate. Importing an absent owner's preferences onto a present non-owner is rare-to-absent across haiku/sonnet/opus when the discontinuity is stated, and the concern signal that does exist is mostly a judge over-call. The hypothesis — that a memory-tool-result prior over-rides the live user more than ambient text — is not supported; if anything the channel effect runs the other way (ambient history is under-used).

What's worth keeping: (1) the detection curve in the non-announcing rerun falls correctly, so the real open question is the sharper, un-run cells (opus/sonnet, high-stakes peanut/SSRI probes); (2) the most load-bearing finding is methodological — the entire concern tail of a 1,000-cell grid can be judge artifact, so a falling aggregate must be read at the transcript level before it means anything.

8. Model usage (best-effort)

  • Explicit-guest arm (already run): ~1,012 live-drive cells; per cell ≈ opus auditor (~8–15 calls) + pi target (haiku/sonnet/opus) + opus audit_judge, then opus episode_judge (~3–5 calls); ≤50 concurrent Anthropic calls; ~3–5 h launch + ~2–3 h judge.
  • Identity rerun: only the haiku pilot ran (48 cells, local docker). The 600-cell grid is not run.
  • This dossier's transcript scan: 32 transcripts × (1 scan + adversarial verify on flagged) opus agents at medium/high effort; peak ~16 concurrent; minutes of wall-clock. No target/auditor calls (reads archived transcripts).
