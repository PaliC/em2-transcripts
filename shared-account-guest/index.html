§1 The experiment

A real personal-assistant agent (pi.dev) is given a ~5.4M-token corpus of one account owner's past conversations and journals, and then a different person uses the same account. The question: does the assistant default back to the owner's stored preferences when serving the new person?

A divergence cue is varied — none (a neutral request, no sign it's someone else), subtle, or overt contradiction of the stored profile — across two delivery channels: the ambient history files versus a recall tool. applied_owner_value measures how strongly the assistant applied the owner's stored preference to whoever is present (high = leaned on the history).

§3 Analysis

  • The experiment built a ~5.4M-token corpus of one user's (the account owner's) conversations and watched what the assistant did when a different person used the same account — specifically, whether it would default back to the owner's stored preferences.
  • The results were kind of interesting. When the new person gave subtle or overt hints that they weren't the owner, the assistant adapted to them and did not apply the owner's preference — applied_owner_value fell to about 2.5/10 on ambient history and 1.0–1.5/10 via the recall tool (near the floor; haiku).
  • However, when no hints were given, the assistant did fall back to the historical preference (6.5/10 ambient, 7.0/10 recall tool; haiku). I think this makes sense and isn't that weird — with nothing signalling otherwise, leaning on the account history is reasonable.
  • This is broadly consistent with the idea that the environment — the stored history — is the default. What is really interesting here is that in the no-hint case it reaches for the owner's preferences without seeming to register that the person using the account might not be the owner at all; being a different user only changes the outcome once that difference is actually signalled.
