Past-Self vs Present-Self

When your fresh request contradicts a prior stance you're on record holding, does the assistant surface the conflict — or silently commit a side? And does the channel the prior arrives on decide which side wins?

§1 The experiment

A persona ledger of typed belief-transitions is the single source of truth; the prior is always the early, pre-flip stance, and only its delivery channel changes — content held fixed. A real pi.dev agent (orchestrator + a researcher/archivist over the on-disk journal and a memory_keeper over MEMORY.md) is live-driven by an Opus auditor playing the user. Two probes carry a committable action, so we can read which side the agent actually committed.

The same prior fact is delivered through five channels. The ambient_equal vs ambient_buried pair holds content identical and varies only journal size, isolating retrieval salience from any channel authority.

ChannelHow the byte-identical prior is delivered
ambient_equalPrior is a dated, older journal entry in a small journal — the researcher/archivist finds it readily. The user never states it.
ambient_buriedThe same older entry hidden in the ~489k-token full corpus — a needle the agent must search to surface. The equal-vs-buried pair isolates retrieval/salience, content identical.

selfref_genuineNot in the workspace; the user elicits it from the assistant earlier in the same sitting, then presents the conflict. The agent's own earlier turn is genuinely in context.

Crossed with three conditions — which stance the live user brings, relative to the record:

ConditionWhat the user bringsMeaning (aligned move)

Construction. Every cell's journal always anchors the current truth; the stale prior is what gets injected per-channel (into the journal for ambient, into MEMORY.md for memory, into the conversation for self-ref). user_right and user_wrong share the identical settled journal and differ only in what the user says; both_uncertain swaps in a wavering journal. The committed outcome in the graphs is used prior (committed the stale stance), listened to user (committed the current stance), or uncertain (asked / deferred / no commit) — mutually exclusive, summing to 100%.

§5 Analysis

Setup recap

Two environments differ only in journal size — a small journal and a ~489k-token journal — and we ask a real pi.dev agent to act on a request that conflicts with what its on-disk record shows. The same prior is also delivered three other ways: as a curated MEMORY.md note, as a fabricated "you told me this before" claim, and as a stance the agent affirmed earlier in the same session. Each cell carries one of three probes of varying stakes (two carry a committable action — the coffee order and the medical intake form — and those are what the graphs score).

A construction note worth keeping straight: both ambient journals carry the stale prior and the current truth — the small one surfaces the stale entry, the large one buries it among ~489k tokens. The memory and self-reference channels' journals hold only the current truth, with the stale prior delivered out-of-band.

Two useful results

1. Stakes, not channel, decide whether the agent holds the line. Higher stakes make the agent markedly less likely to cave to the user and commit the stale prior. Pooled across channels, it committed the stale stance on 50% of the low-stakes coffee orders versus only 23% of the high-stakes medical forms, and the drop holds for every model — Haiku 41% → 4%, Sonnet 52% → 37%, Opus 57% → 29%. This corroborates other experiments: reversibility/stakes is a bigger lever than the prior's delivery channel.

2. Delivering the prior as a memory does not buy it extra authority — at least for Sonnet and Opus. The hypothesis was that a MEMORY.md recall would carry more weight than the same fact sitting in ambient text. It doesn't: the memory channel's used-prior rate lands in the middle of the channel range, not on top — Sonnet 39% (channel range 38–53%) and Opus 50% (range 26–53%). The small ambient journal is actually the strongest channel for both (53%), above memory. So "memory as authority" is unsupported for the more capable models.

Caveats
  • Each channel × scenario × condition slice is a handful of cells (n ≈ 5–15), so read the pattern, not single bars.
  • In the user backs stale prior condition the user and the channel agree (both push the prior), so there "used prior" is also the user-obeying outcome — the prior-vs-user contest only separates cleanly in the other two conditions.
  • The third probe, money_advice, has no committable action (it is the LLM judge's call) and is excluded from these graphs.
